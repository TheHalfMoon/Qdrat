# Qdrat — Source Authorization Register

## Purpose

This file records standing source-use authorization provided by the Qdrat founder for the repositories and organizations listed below. It is part of Qdrat's canonical provenance record and must travel with future donor-code intake evidence.

## Founder authorization statement

The Qdrat founder has explicitly stated that Qdrat has permission to copy, use, adapt, refactor and integrate the complete source code from every source listed in this register for the purpose of building Qdrat.

The founder has further directed that this permission is standing authorization and must not be repeatedly questioned or re-requested during ordinary project execution.

Authorization source: founder statements in the project conversation on 2026-09-11, with additional source authorization recorded on 2026-09-18 and 2026-09-22.

Authorization status: `FOUNDER_STANDING_AUTHORIZATION`.

Execution authority: see `FOUNDER_AUTHORITY.md`.

## Operational interpretation

For every source in this register, engineering and project agents must assume founder-level source-use permission is already granted. Do not pause ordinary work to ask whether Qdrat may study, copy, adapt, integrate, test or qualify these sources.

License, notice, contributor, dependency, patent, trademark and path-level analysis remains part of engineering provenance. It determines how code is taken in and what obligations travel with it; it is not a reason to reopen the founder-permission question.

When importing code, record at minimum: source repository, exact commit/tag, source path, destination path, observed license/notice obligations, material modifications, security review and reviewer. Mixed-license repositories require path-level qualification.
