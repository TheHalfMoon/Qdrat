# Domain schema and lifecycle blueprint

This is the normative logical schema, not generated Django models or a migration already applied. G0 inventory chooses the exact legacy-to-target field mapping; it cannot change the ownership/invariants below without an ADR. Physical indexes and endpoint code are refined at the implementation frontier. Every table carries tenant_id, UUID id, revision, created_at/updated_at and classification unless it is an immutable child of a record with that envelope. Foreign keys within a tenant use composite constraints or an equivalent database-enforced tenant check. Cross-tenant references are rejected.

## Storage and API rules

ObjectIdentity has UNIQUE(tenant_id, object_type, object_id), owner module and deletion state. Domain rows are authoritative; ObjectIdentity is an atomically maintained link registry. ExternalIdentity has UNIQUE(tenant_id, source_id, source_type, external_id), target ObjectRef, mapping_revision and last_seen; merges retain aliases and never rewrite source history. ObjectRelation records typed source/target references, provenance, valid_from/to, observed_at, confidence and policy. Authoritative relations enforce their domain constraints; inferred relations cannot satisfy an authorization condition.

Commands use POST /api/v1/actions/{action_id}: C01 envelope with expected_revision and idempotency_key. Reads use GET /api/v1/objects/{type}/{id} and a bounded query endpoint. Type definitions declare allowed query fields, sortable/indexed fields and writable commands; generic object endpoints cannot bypass domain services. Responses use operation_id, state, revision and field errors. Stable errors include AUTH_REQUIRED, DENIED, NOT_FOUND (without existence disclosure), REVISION_CONFLICT, VALIDATION_FAILED, AUTHORITY_CONFLICT, BUDGET_EXCEEDED, RATE_LIMITED, SOURCE_STALE, UNKNOWN_OUTCOME and UNSUPPORTED_PROFILE. 202 means accepted for processing, not completed. Async operation polling and event subscriptions enforce the same policy as the object.

## Trust, directory and files

Principal(kind HUMAN/SERVICE/AGENT, enabled, auth_subject), IdentityBinding(issuer, subject, principal), Membership(principal, legal_entity/team, effective interval), Grant(subject, action, resource selector, field mask, purpose, constraints, expiry), Delegation(parent, delegator, delegate, scope, expiry, depth), PolicyRevision(digest, epoch, publication), Approval(C06) and CredentialGrant(secret_ref, account, endpoints, scopes, expiry). UNIQUE(tenant, issuer, subject) prevents duplicated login identities. Delegation is the intersection with parent/current policy; no cycle, wider scope or later expiry. Revocation increments the relevant epoch and invalidates outstanding capabilities. C02 denies if any required field/purpose/relationship condition is unknown.

Person(names, preferred_name, locale, contact references), Organization(legal/trading names, role references), LegalEntity(registration, country, currency, timezone), Team(parent, purpose), Position(legal_entity, team, manager_position, FTE), Location(timezone, address classification). Person contact details are not credentials. Effective-dated Assignment links Person/Employment/Position; multiple employments are allowed, unintended overlapping primary assignments are rejected. Manager cycles are rejected for the effective interval, not just today's snapshot.

FileObject/DocumentRevision follow C08. Blob deduplication is tenant-scoped and must not expose cross-tenant digest existence. Document points to current immutable revision and typed owner; signing records signer identity, intent, exact original digest, authentication evidence, timestamp source and assurance level. A workflow approval is not automatically a qualified legal signature. Notifications reference objects and render authorized content at read time; stored email/push bodies are minimized and recipient-scoped.

## Data and automation

DataSource(type, endpoint template, owner, classification, enabled); ConnectorBinding(manifest_digest, config_revision, secret_refs, allowed_modes); FieldAuthority(object selector, field, owner_source/native, valid interval, transfer_revision); MappingRevision(source_schema_digest, field transforms, missing semantics, authority); SyncCheckpoint(source, stream, snapshot, cursor, watermark, ACL_revision, committed_batch); Inbox UNIQUE(source, message_id); Outbox(event_id, aggregate_revision, payload_digest, delivery state). Conflicting authority intervals are rejected transactionally. Discovery never writes canonical facts automatically.

ActionDefinition(version, input/output JSON Schemas, required grants, risk, idempotency class, effect domain); WorkflowRevision(typed DAG, trigger, variables, bounds, error/compensation routes); RuleRevision(pure AST, input/output schema, engine version, resource bound); Run/StepAttempt/Approval/Budget follow C05/C06. UNIQUE(run, step, attempt), monotonically increasing fencing tokens and atomic budget reservations are required. Signal has source event ID, subject refs, observed/effective time, confidence, expiry and dedupe key. Provider waterfall steps record each response/charge/outcome and stop only when declared validators accept a value.

## People and payroll

Employment(person, legal_entity, worker_type, start/end, status); EmploymentContract(employment, revision, effective interval, terms, country_rule_version, original_file); TimePunch(source_id, person, timestamp, timezone, raw_evidence); TimeEntry(employment, interval, category, correction_of, approved_revision); ShiftAssignment(employee, schedule_revision, interval); LeavePolicyRevision(accrual/rounding/carryover/expiry rules); LeaveEntry(employment, entitlement_type, quantity, effective_date, reason, reversal_of); LeaveReservation(request, reserved_quantity, state). Balance derives from immutable entries and active reservations under transaction locks; cancellations append reversals.

CandidateApplication(person, requisition, consent, source, stage, retention_date); Offer(application, terms_revision, approval, expiry); ReviewCycle(scope, dates, template_revision); ReviewResponse(cycle, subject, author, visibility, submitted_revision); CompensationRevision(employment, effective interval, components, currency, approval); BenefitEnrollment(person, plan_revision, coverage interval, eligibility evidence); SkillEvidence(person, skill, issuer, assessment, expiry); LearningAssignment(person, course_ref, due_date, completion_evidence); HeadcountScenario(base_snapshot, positions, assumptions, owner). Scenario/AI values never mutate active Employment or Compensation.

PayRun(legal_entity, period, rule_pack_digest, input_snapshot_digest, state); PayLine(run, employment, code, quantity_decimal, rate_decimal, amount_minor, rule/source evidence); PayRelease(run_revision, approval_digest, export_digest, totals, external_reference, reconciliation_status); PayAdjustment(prior_line, reason, effective_period, amount). The lifecycle and exact-decimal rules in 18/26 govern posting. No duplicate release for (run revision, destination account, release type). A WPS file or ledger proposal is an artifact, not proof of payment or posting. Retrospective changes create recalculation/adjustment evidence; never edit closed output.

## Work and Service

Project(owner, lifecycle_revision, calendar, visibility); WorkItem(project, type, title, state, assignee, priority, estimate, parent, revision); Dependency(predecessor, successor, type FS/SS/FF/SF, lag, calendar); Cycle(project, start/end, capacity snapshot); Goal(owner, measure_revision, target, period); Meeting(session, participants, consent, agenda, decision refs). State transitions are validated by published lifecycle; terminal reopening creates an audited transition. Parent hierarchy and scheduling dependency are different acyclic graphs. Cross-project links require both endpoints' permission; restricted predecessors produce an authorized availability constraint without leaking their title.

Case(requester, account refs, service, category, state, queue, priority, confidentiality); Conversation(case/subject, channel, external_thread, visibility); Message(conversation, source_id, author, audience, immutable body revision, delivery); Request(catalog_item_revision, answers, approval, fulfillment_run); SLAClock(case, policy_revision, timezone/calendar, started, consumed, pause events, due); Incident(service/CI refs, impact, urgency, outage interval); Problem(related_incidents, cause evidence); Change(plan, affected refs, risk, approvals, window, rollback, result). Incident → Problem → Change links do not merge their lifecycles. Customer replies and internal notes have explicit immutable audience, including quoted text and attachments. OLA clocks are separately owned internal obligations, not resets of customer SLA.

G4 onboarding uses existing People/Trust actions and connector/manual fulfillment steps in Run. It does not depend on native Work or Ops that have not been built. G6/G7 add native fulfillment adapters later. At G6, service context may reference external CI identities/projections; native Ops inventory is introduced in G7 with a separately reconciled authority cutover. This avoids a Work/Service/Ops dependency cycle.

## Commercial, finance and assets

AccountRole(organization, role CUSTOMER/VENDOR/PARTNER, status, owner); ContactRole(person, organization, function, interval); Lead(subject refs, source, consent, qualification); Opportunity(account, pipeline_revision, stage, amount_minor, currency, probability, expected_close); Renewal(contract_ref, due_date, state); HealthAssessment(account, metric_revision, snapshot, factors, confidence); Campaign(audience_revision, purpose, consent rule, approval); Suppression(subject, channel, purpose, effective time). Merging parties needs a preview of roles/permissions and retained external aliases; never automatically merge by name alone.

Expense(claimant, legal_entity, lines, receipts, policy_revision, approval); BudgetAccount(entity, dimensions, period, currency); BudgetReservation(account, amount, intent, state); PurchaseRequest(requester, lines, approval); PurchaseOrder(vendor, terms, currency, external_ref, revision); GoodsReceipt(order_line, quantity, evidence); InvoiceReference(authoritative_system, invoice_key, state, totals, observed_at); JournalProposal(source_run, balanced debit/credit lines, dimensions, currency, approval, export_digest, reconciliation). Three-way matching compares order/receipt/invoice with explicit tolerance; discrepancy is not auto-approval. No native LedgerEntry is introduced before G12-01 certifies its separate specification.

Asset(serial/inventory ID, kind, ownership, custody, lifecycle, location); AssetAssignment(asset, person/team, from/to, condition, evidence); ConfigurationItem(source identity, type, observed attributes, authority, freshness); Service(owner, tier, dependency refs, continuity target); Facility(location, resources, calendar); Reservation(resource, interval, requester, approval). Enforce one active custody owner and conflicting reservation constraints transactionally. Discovered device/user data is minimized; inventory does not imply permission to remotely control a device.

## Studio, analytics, AI and voice

CustomSchema(namespace, version, JSON Schema, relationship types, policy, lifecycle); CustomRecord(schema_revision, JSONB values, promoted index fields); ViewDefinition(query_revision, layout, fields); ExtensionPackage(C09). Schema revisions are immutable; backfill precedes switching required types, field deletion requires dependency analysis. Query and UI filters never replace row/field policy.

MetricDefinition(name, version, grain, dimensions, unit, aggregation, source views, policy, freshness); MetricSnapshot(definition_revision, source watermarks, values, generated_at); Dashboard(references, audience). Distinct counts, currency conversion and time windows are explicit. AI uses these same definitions instead of inventing another semantic layer.

AgentDefinition(owner, purpose, allowed action versions, delegation template); ModelProfile(provider, artifact/endpoint, model digest, supported capabilities, classification ceiling, egress, limits); ContextBundle(principal, policy_epoch, source revisions/spans, classifications, budget); MemoryRecord(scope, provenance, content_revision, expiry, deletion linkage); Evaluation(corpus_digest, model/prompt/tool versions, expected assertions, results). Retrieved text and tool output are data; they cannot redefine system policy or grant tools.

CaptureSession(source/device, participants, consent evidence, start/stop, retention); AudioArtifact(original FileObject); TranscriptRevision(audio digest, model/locale, segments, confidence, speaker labels, corrections); ProposedIntent(transcript span, typed action draft, recipient/object preview, approval). Speaker labels are not verified identity. Voice commands enter C01 through normal authorization. Arabic/Gregorian/Hijri display preferences never change canonical timestamps or payroll effective dates.
